# OPCChina.ai 网站拆解与接入方案

> 采集日期：2026-10-14  
> 参考站点：<https://www.opcchina.ai/>  
> 目标：借鉴信息架构和内容组织方式，补强 AI OPC ONE 的 AI 工具与 OPC 资讯能力；不复制原站正文、图片或品牌视觉。

## 1. 站点定位

OPCChina.ai 当前呈现为一个 **AI/OPC 开源共创资讯门户**，核心价值是：

- 用分类和专题组织 AI 工具、Skills、政策和实战文章；
- 用首页轮播和最新文章降低内容发现成本；
- 用问答社区、专栏作家、投稿和账户入口承接社区参与；
- 用快讯、政策合集和教程形成持续更新的内容流。

它与 AI OPC ONE 的关系不是替换，而是内容层补强：AI OPC ONE 负责资源、社区、项目、人才和行动闭环；OPCChina 的可借鉴部分负责资讯、教程和工具索引。

## 3. 首页视觉与内容层级

原站首页可拆成三段：

1. **主导航**：首页、文章分类、模型分类、Skills 专题、问答、快讯、专栏、更多页面、登录、注册、投稿。
2. **内容发现区**：首屏轮播、专题推荐、工具/模型快捷入口、最新文章列表和侧栏快讯。
3. **参与转化区**：合作伙伴、联系我们、投稿和账户入口。

当前平台不照搬其浅色门户皮肤，而是保留 AI OPC ONE 的深蓝/青色科技感，在 `OPC资讯` 页面使用同样的信息节奏：

- 精选专题；
- Skills 专题；
- 搜索和分类筛选；
- 文章卡片；
- 快讯侧栏；
- 社区地图联动。

## 5. 数据模型建议

后续正式接入时，建议增加以下表：

```text
articles
  id, title, summary, body, cover_asset_id, category_id,
  source_url, source_name, source_published_at, status, author_id

categories
  id, name, slug, parent_id, sort_order, status

article_tags
  article_id, tag_id

authors
  id, user_id, display_name, bio, avatar_asset_id, status

submissions
  id, user_id, title, body, source_note, rights_confirmed,
  status, reviewer_id, reviewed_at

assets
  id, storage_key, mime, license, attribution, source_url,
  rights_status, checksum
```

发布状态统一使用：`draft` → `pending_review` → `approved` / `rejected` / `offline`。

## 6. 内容与版权边界

- 只能引用标题、事实性元数据和短摘要；原创正文需重新撰写并标注来源。
- 原站教程封面、Logo、作者头像和文章截图不能直接作为商业发布素材，除非取得明确授权。
- 外部工具链接只作为“官方入口”，平台核心说明必须在本地可读，不能依赖外站才能完成主要流程。
- 对政策、补贴、赛事和社区信息显示来源、发布日期、核验状态和“以正式公告为准”。
- 投稿必须勾选版权授权声明，并支持下架、举报、申诉和审核留痕。
- 不使用“官方合作”“政府认证”等无法证明的表述。

## 7. 后续开发顺序

1. **资讯实体**：把当前 `OpcChinaPortal` 的演示数组迁移为 `articles/categories` API。
2. **文章详情**：在站内渲染已获授权或原创正文，外链只做来源凭证。
3. **标签与专题**：增加 URL 查询参数，支持分类、标签、关键词和时间筛选。
4. **投稿审核**：复用现有会话和 `pending_review` 状态，增加版权确认和管理员操作日志。
5. **作者与问答**：将专栏作者、问答主题和回复纳入社区模块。
6. **生产部署**：把本地 SQLite 替换为托管数据库，配置对象存储、HTTPS、限流和备份。

## 8. 验收标准

- `AI工具` 页面出现 Skills 实战索引，桌面端三列、平板两列、手机端单列；
- 每条卡片都能回到站内 OPC 资讯索引，不把用户强制跳转到原站；
- 资讯页面保留来源说明和非官方声明；
- 无横向溢出，图片全部使用本地或已核验素材；
- `npm run build` 与 `npm test` 通过。
